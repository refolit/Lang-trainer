# План развития: синхронизация + мультиязычность + многопользовательность

> ТЗ-чеклист. Здесь зафиксированы все принятые решения и порядок работ.
> Исполняется фазами; каждая фаза, меняющая `index.html`, проходит через утверждение версии у пользователя (правило: Claude Code не меняет версию сам).

## Принятые решения (не менять без договорённости)

| Вопрос | Решение |
|---|---|
| Хранение в Supabase | Гибрид (вариант C): карточка целиком в `data jsonb` + `lang` + `user_id` + `updated_at`. Для будущих серверных выборок — generated-колонки `box`, `starred` (добавляются позже, по факту необходимости, без миграций). |
| База слов | Небольшой стартовый каталог-пример (общий) + **личный набор карточек у каждого пользователя на каждый язык**. Слова создаёт пользователь. |
| Аутентификация | **Email OTP (magic link)** + RLS с первого дня. `anon`-ключ публичный по дизайну — безопасность даёт RLS, а не секретность ключа. |
| Конфликты | **Last-write-wins по `updated_at` на уровне каждой карточки**. Календарь `activity` склеивается по датам (max). Запасной вариант при рассинхроне часов — целочисленный `rev`. |
| Кнопка «Синхронизировать» | Экран **Словарь**: поиск влево (половина ширины), кнопка справа, строка статуса под ними. |
| Аудио | Синхронизируем **отдельной фазой после** стабильной синхронизации карточек (Supabase Storage). |
| Мультиязычность | Контент — сейчас (поле `lang` в данных); перевод самого **интерфейса** — потом. 5 нижних табов **у всех языков** (в т.ч. «Письмо»). |
| Режим «Письмо» | Есть **во всех языках**. Китайский — кистью (HanziWriter, порядок черт). Английский/турецкий — печать на клавиатуре. Арабский — печать (RTL) + позже аналог HanziWriter для вязи. `has_strokes` управляет только внутренностью режима, а не видимостью таба. |
| Доступы | **Пароли в чат не передаются.** Я готовлю SQL/инструкции — пользователь сам выполняет шаги в дашборде. |
| Каноническая папка | `D:\! MyProjects\Github\Lang trainer\Lang trainer` (git + GitHub Desktop). Боевая папка `D:\! MyProjects\Claude original\hanzi-trainer` заморожена. |
| Переименование | Внутри приложения и в описании → «Language Trainer». Сам репозиторий `Lang-trainer` пока **не** переименовываем (не ломать живую ссылку Pages). |

## Ключевая схема данных (черновик, для SQL-скрипта в Фазе 2)

```
languages      (code PK, name, rtl bool, has_strokes bool, sort_order)
profiles       (id PK → auth.users, email, ui_lang, active_lang)
cards          (id text PK, user_id → auth.users, lang, data jsonb, updated_at tz)
user_settings  (user_id PK → auth.users, data jsonb, updated_at tz)
user_stats     (user_id, lang PK, data jsonb, updated_at tz)
catalog_items  (id, lang, kind, text, pinyin, translation jsonb, tag)
```

- `cards.data` = объект карточки как есть (`item` из IndexedDB) + поля `lang`, `updated_at`.
- RLS: для всех пользовательских таблиц `auth.uid() = user_id`; `catalog_items` — `select` всем.
- Аудио: bucket `recordings`, путь `user_id/<card_id>/<speed>.mp3`; в карточке только ссылка.
- Generated-колонки для будущих выборок (позже): `box`, `starred` из `data`.
